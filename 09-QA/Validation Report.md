# Validation and completion report

Date: 2026-10-08. Repository: figma-design-skill. Scope: full architecture/instruction audit and local implementation. Work was sequential, beginning with a read-only inspection of all 61 original files. No original files, domain folders, license or pre-existing user changes were removed.

## Outcome

The repository now has one discoverable skill, one source hierarchy, task-based specialist retrieval, operational shared standards, a classified reference/intake system, critique/QA, component and Figma engineering contracts, handoff, governance and representative evaluation scenarios. The architecture preserves the numbered domains and places new material at a clear owner.

57 original files were changed by this audit; 55 files were created. Two overlapping guides were consolidated into canonical guides with retained entry paths. No original file was removed. Three pre-existing edited files and the MIT license retain their captured bytes.

The work closes identified authoring and retrieval gaps. Elite design output is a target, not an empirically established result: written scenarios and author review cannot establish actual visual polish, user success or runtime accessibility.

## Original problems

- Empty SKILL.md, README, contributor/change records and six foundation modules prevented reliable entry and shared reasoning.
- Four competing precedence models and supreme-authority claims made decisions inconsistent.
- 53 of 322 declared dependency edges pointed to nonexistent files.
- Large repeated lifecycle, governance, token and QA checklists buried specialist behavior; a mandatory ten-stage process and fixed alternatives overreached small tasks.
- Empty token, Figma, documentation, handoff, QA and governance domains left important promises unimplemented.
- Fixed grids, radii, mobile sheets, sidebar/topbar templates, mandatory illustrations/skeletons and broad variant families encouraged repeated formulas.
- Component semantics, service truth, recovery and evidence limits were under-specified.
- No shared source evaluation, runnable intake, critique calibration or representative tests existed.

See [Architecture Audit](Architecture%20Audit.md) for the original and recommended maps, structural rationale, dependencies and contradictions. [File Audit](File%20Audit.md) assesses every original; [instruction-audit.json](instruction-audit.json) records 57 files across all 51 requested dimensions (2,907 qualitative assessments).

## Final architecture

Project requirements/user goals -> existing project system -> UX/accessibility -> platform conventions -> production patterns -> inspiration -> design decision -> critique -> validation.

AGENTS.md is a concise operating contract. SKILL.md and Knowledge Graph route relevant work; shared owners prevent global repetition. Existing specialist modules govern controls and tasks. Tokens and Figma production describe actual reuse mechanisms. References are central evidence records. Documentation/handoff define reviewable implementation intent. QA/evaluations separate specified behavior from observed results.

Scoped guidance exists only for differing Figma, evaluation and preserved-legacy responsibilities. Root entrypoints explicitly link scoped contracts, since a root-started session may not automatically discover descendant AGENTS.md files. This follows the current [official Codex instruction-discovery documentation](https://developers.openai.com/codex/guides/agents-md/).

## Major instruction improvements

- One exact six-level source order; conflicts with accessibility are surfaced with a conforming alternative.
- Existing system values/bindings own visual decisions; provisional foundations are defined only when a system is absent.
- Reasoning starts with task and information order, then interactions/states, then composition/style. Alternatives have meaningful trade-offs and failure conditions.
- Context-specific density and layout distinguish financial comparison, conversation, editorial reading, analytical monitoring and creative work.
- Native table versus interactive grid, menus versus listboxes/comboboxes, and modal versus nonmodal panels have different contracts.
- State truth separates no data, no matches, denied, pending, stale, partial, failure and unknown status. Payments reconcile uncertainty before retry.
- Component APIs, semantic roles, meaningful variants, invalid combinations, properties and code mapping replace mechanical variant multiplication.
- WCAG 2.2 AA checks distinguish 24x24 CSS-pixel target minimum/exceptions from enhanced 44x44 AAA, with contrast, focus, keyboard and reflow requirements. Native metrics require current platform guidance.
- Figma production inspects existing assets, reuses IDs/bindings, checks supported properties, reads back structure and inspects actual rendering.
- Evidence distinguishes intended, inspected, observed and user validated. Static Figma/specification evidence cannot prove screen-reader or backend behavior.

## Reference architecture

One shared area uses ten category tags rather than duplicated libraries or mostly empty folders. Every registry entry supports source, URL/local source, product/studio, platform, screen/flow, pattern, reason, qualities, separate interaction/visual/UX principles, rejected details, system adaptation, review/check dates, status and evidence limits.

The registry has 16 records: WCAG, ARIA patterns, Figma documentation, Apple HIG accessibility, Carbon, Atlassian, Fluent, Radix, NN Group, Mobbin, Awwwards, CSS Design Awards and a shipped GOV.UK service entry. Fifteen records are reviewed within their stated scope; Awwwards is unavailable. Mobbin/CSS are catalog reviews, not tested product/site flows. GOV.UK is an inspected entry page, not an executed payment flow. Apple accessibility content was recovered through first-party DocC JSON after its landing page exposed only a JavaScript shell.

The intake CLI queues metadata in one inbox without fetching or executing sources. Inspection extracts principles before UI and translates them through local components/tokens. Pending/uninspected/unavailable entries cannot claim extracted principles or invented review dates. Standards and inspiration have distinct authority.

See [references/README.md](../references/README.md), [references/Reference Intake.md](../references/Reference%20Intake.md), [references/catalog.json](../references/catalog.json) and [references/catalog.schema.json](../references/catalog.schema.json). Primary sources are linked in records and next to applicable rules; no external library was copied into the repository.

## Remaining gaps and human decisions

No consequential repository-architecture decision remains blocked. Project-specific design work still requires the actual library/token bindings, brand/content, supported platforms, permissions/security/domain policy, service behavior and success evidence. These are external project inputs, not placeholder modules to invent.

Independent fresh-session generation, rendered Figma artifacts, runtime keyboard/assistive-technology behavior, realistic data performance and usability studies were not run. Future evidence can establish whether outputs reach the intended craft standard. No supplied Figma file, product runtime, participants or internal system existed in this task.

Reference-specific limits remain: Awwwards retrieval failed; catalog entries need specific flow/site inspection before behavioral claims; Apple topics beyond inspected accessibility need task-specific review. No user decision is needed to retain these truthful statuses. A future authorized change to the three protected files should update the preservation policy openly.
