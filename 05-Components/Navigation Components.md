# Navigation components

Canonical navigation guide; Navigation.md is a compatibility route. [Information Architecture](../01-Foundation/Information%20Architecture.md) owns destinations, labels and relationships.

Select top/side/bottom/rail/tree navigation by destination count, hierarchy, frequency, input and available space. A sidebar is not an automatic dashboard requirement. Visible high-frequency destinations improve discovery; overflow supports less frequent work.

Separate global destinations, local views, contextual links and utility actions. Tabs switch related views; links navigate. Breadcrumbs express hierarchy, not browsing history. Steppers show genuine task stages, not decorative progress.

Current location, selected choice, focused item and expanded branch have distinct states. Use links and current-page semantics for destinations; use the matching tab/tree pattern for composites. Plain nav links use Tab, not compulsory arrow navigation. Skip-to-content and labeled landmarks aid repeated web navigation.

Preserve deep-link entry, browser/platform back, query, selection and scroll return. Responsive changes keep destinations reachable and current location clear. An icon rail needs names and a usable label/context route.

Specify long labels, overflow, no accessible destinations, permission changes and hidden/disabled policy. Do not expose sensitive route names merely to explain unavailable access.

Verify orientation and task reachability at narrow width, text scaling, keyboard/touch and supported platform. [Accessibility](../01-Foundation/Accessibility.md), [Responsive Design](../01-Foundation/Responsive%20Design.md)
