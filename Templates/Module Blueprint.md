# Module blueprint

Use only the sections that clarify this module's ownership. Do not repeat the repository hierarchy, accessibility rules or entire lifecycle in every specialist.

## Purpose and boundary

State the task this module resolves, what belongs elsewhere and the canonical related owners.

## Decisions

For each consequential choice record trigger, recommended behavior, rationale, trade-off, failure condition and the alternative. Use task-specific examples rather than a universal layout or fixed number of options.

## Contract and verification

State relevant states, content constraints, responsive/input behavior and implementation assumptions. Link shared standards. Define evidence needed to check the intended outcome and distinguish specification from observation.

## Relationships

Use working relative links to dependencies and downstream consumers. Cite primary sources near externally derived rules; link shared reference records for reusable observations.
