# User journey mapping

Owns complete flow, entry/exit and backstage dependencies. Map only the relevant journey.

Represent trigger -> intention -> action/decision -> system response -> next state -> completion/exit. Include deep links, returning users and alternate entry when they change orientation.

For consequential steps record preconditions, information, permission, pending/committed status, interruption, failure, retry safety and recovery. Distinguish observed emotions from hypotheses. Add a service blueprint when support, approvals or background work controls the experience.

A transfer journey includes recipient lookup, amount, review, authorization, pending status, receipt and uncertain-commit recovery. A modal screenshot covers one moment.

Verify back/cancel without unintended loss, resume, access/timeouts, completion and next action. Preserve task logic across platforms while adapting navigation/input.

Deliver a state/transition table or diagram plus unresolved business rules. Connect [Information Architecture](Information%20Architecture.md), [Interaction Design](Interaction%20Design.md) and [Pattern Principles](../06-Patterns/Pattern%20Principles.md).
