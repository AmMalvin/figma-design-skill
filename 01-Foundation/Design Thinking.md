# Design thinking

Use for uncertain problem solving. Discovery/definition and exploration/selection are iterative activities, not gates for every edit.

Frame the problem from evidence and assumptions. Investigate root causes when several mechanisms could explain a symptom. A "How might we" prompt should open approaches without smuggling in the UI.

Compare different task sequences, information timing and interaction models before cosmetic variations. Sketches, analogies and ideation techniques earn their use only by exposing a real alternative. Do not require a named technique or fixed idea count.

Select for task fit, accessibility, system alignment, effort and risk. Test the assumption likely to invalidate the model. Reframe only when evidence challenges the problem; otherwise revise the affected behavior.
