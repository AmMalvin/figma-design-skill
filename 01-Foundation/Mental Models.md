# Mental models

Owns expectations and conceptual mapping. Identify what users believe an object/control does; compare that with actual behavior.

Reuse familiar controls and domain vocabulary. Essential actions need visible routes; shortcuts accelerate them. Explain necessary new concepts where they become relevant.

Distinguish affordance (possible action), signifier (cue), mapping (control/result) and feedback (consequence). Interactive cards need a clear destination/action; informational surfaces do not need hover styling.

Validate expectations by expertise, domain and platform. A file tree fits hierarchical resources, but is a poor default for a shallow task service. Breadcrumbs reflect hierarchy, not history.

Originality can live in product logic and expressive composition; reinventing standard controls needs evidence. Connect [Information Architecture](Information%20Architecture.md) and [Interaction Design](Interaction%20Design.md).
